# Contributing

## Layout

```
src/
  Core/        what every Reeds API shares: the client (credentials, token, HTTP, retries,
               idempotency keys), errors, pages, files, webhook signatures
  Exception/   one exception per kind of failure
  Shipping/    the Shipping API module: one class per resource, Events, and Types (generated)
  Laravel/     the service provider and the facade
  Reeds.php    one client, a property per API module
  Webhooks.php signature checks and test events, for every API
scripts/       generate.php: spec/*.yaml -> src/*/Types.php (PHPStan array shapes)
spec/          copies of the APIs' OpenAPI specs, taken from sendx-api by the sync-spec workflow
tests/         PHPUnit (unit), tests/E2E (the real API in Test mode), tests/smoke (real HTTP), tests/Readme
```

The method names match the Reeds Node.js and Python libraries, so code reads the same in each language.

## Checks

No PHP on your machine? Docker is enough:

```sh
docker run --rm -v "$PWD":/app -w /app composer:2 composer install --ignore-platform-req='ext-*'
docker run --rm -v "$PWD":/app -w /app php:8.1-cli vendor/bin/phpunit --testsuite unit
docker run --rm -v "$PWD":/app -w /app php:8.1-cli vendor/bin/phpstan analyse
docker run --rm -v "$PWD":/app -w /app php:8.1-cli sh -c 'php -S 127.0.0.1:8099 tests/smoke/server.php >/dev/null 2>&1 & sleep 1; php tests/smoke/smoke.php'
```

`composer.json` pins the dependency resolution to PHP 8.1 (`config.platform.php`), so the same dev tools run on every supported PHP; CI tests 8.1 to 8.4.

## A spec change

The sync-spec workflow opens a pull request when sendx-api deploys a changed spec to production. `composer generate` rebuilds `src/Shipping/Types.php`. `tests/CoverageTest.php` fails until every operation in the spec has a method and every webhook event type is in `Events::TYPES`. Add the method, a test, a CHANGELOG entry, then merge.

## Adding a Reeds API

1. The API follows the shared rules (path `/<api>/v<n>`, OAuth scope, envelopes, cursor pagination, Idempotency-Key, `Retry-After`, `X-Request-Id`, one webhook format). Its spec is in sendx-api's `openapi/`.
2. Add it to `APIS` in `scripts/generate.php` and to the sync-spec workflow; put its spec in `spec/` and run `composer generate`.
3. Add `src/<Api>/` (one class per resource, `Events`), a property and accessor method on `Reeds`, the accessor on the facade's docblock, and its operation map in `tests/CoverageTest.php`.
4. Add its end-to-end scenario to `tests/E2E/`.
5. Release as a minor version.

## Webhook test vectors

`tests/fixtures/webhook-vectors.json` is generated by sendx-api's own signing code, so the library and the server can't drift. Every Reeds library runs the same file. Don't edit it by hand.

## Releasing

Packagist publishes from git tags; there is no release workflow.

1. Update `Version::VERSION` in `src/Version.php` and the CHANGELOG (a test checks they agree).
2. Merge to main once CI is green, then push the tag `vX.Y.Z`. Packagist's GitHub hook picks it up within a minute.
3. The first time only: submit `https://github.com/SendX-hq/reeds-php` on packagist.org under the company account, and enable the GitHub hook.
